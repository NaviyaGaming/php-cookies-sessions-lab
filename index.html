How HTTP, Cookies, and PHP Sessions Work Together

HTTP is stateless. A Cookie stores small data directly inside the user's browser and sends it with every request. A PHP Session stores data on the server inside /tmp/sess_... and uses a single browser cookie named PHPSESSID as the locker key!

Architecture Reference

Cookies vs. Sessions in PHP

Both solve HTTP's statelessness, but they differ fundamentally in where data lives, how secure it is, and when it expires.

Feature / Criteria PHP Cookies PHP Sessions
Storage Location Client-side (User's Web Browser SQLite/text file). Server-side (File in /tmp/sess_..., Redis, or Database).
Security & Tampering Lower Users can inspect, edit, or spoof cookies in Browser DevTools. Never store passwords or roles! High Data stays hidden on the server. Only a random PHPSESSID token is sent to the browser.
Maximum Data Size ~4 KB (4,096 bytes) per cookie (sent on every HTTP request, slowing bandwidth if large). Virtually Unlimited (Limited only by server disk space or PHP memory_limit).
Data Types Supported Strings only (Arrays/objects must be manually json_encode()'d). Any PHP Type (Strings, Integers, Arrays, Booleans, Objects — auto-serialized by PHP).
Lifespan / Expiry Configurable via time() + $seconds. Can persist for days, months, or years across browser restarts. Ends when the user closes the browser or after server inactivity (session.gc_maxlifetime = 1440s / 24 mins).
